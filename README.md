# くくめくり

バラバラに並んだ 100 マスの数字カードの下に、絵が1枚かくれている。
**えらんだ段の九九のこたえだけ**をタップするとそのマスがめくれて、絵が少しずつ見えてくる授業用アプリ。

## 2つの形がある

| | 何 | どこ |
|---|---|---|
| **部屋版**（本番） | クラスごとに部屋を作り、先生が全員の進み具合を見られる | `app-src/`（Next.js＋Cloudflare Workers） |
| **単体版**（保険） | ネットも部屋もいらない。1枚の HTML だけで動く | `index.html`＋`art/` |

授業では部屋版を使う。単体版は「ネットが落ちた」「Workers が止まった」ときの逃げ道として残してある。
中身（盤面の作り方・ルール・絵）はまったく同じ。

## 対象と使いどころ

- **対象**：小2（九九をこれから覚える／覚えはじめ）
- **使いどころ**：九九の導入〜定着期。「3ずつ増える数」を自分で唱えながら探す活動。
  数がバラバラなので、九九を唱えて探さないと絵にならない。
- スクールタクトで 3のだん を紙（PNG）で一緒にやったあと、残りの段をアプリで自由に進める想定。

## しくみ

- 絵は45マスぶんあるが、こたえが入っているのは **36マス**（9つのこたえ × **4つずつ**）。
  残りの **9マスはわざと穴**（こたえでない数）にしてある。
  → 絵が半分見えてきても「この辺も絵だからめくれるはず」が通じない。
    ちゃんと数を見ないと、5回に1回くらいお手つきになる。
  → 穴の場所は**やるたびに変わる**（同じ絵でも配置が毎回ちがう）。
- 絵の外（55マス）には、**その段のこたえを絶対に置かない**（1〜n×9 のうち n の倍数でない数）。
  → 「その段のこたえを全部めくる」で、めくる場所が一意に決まる。
- **順番は問わない。** 3から順でも、いきなり27でもよい。判断させたいのは
  「3のだんのこたえかどうか」の1つだけにしぼる。
- パネルに **3×1＝？ 〜 3×9＝？** の九九を9つ並べて常時出しておく。
  **こたえは さいしょ「？」で かくれている**（ヒントボタンで見せ／かくしを切りかえ）。
  その数を4つ全部めくると「3×2＝6」のように**こたえが埋まる**。
  → かくしたまま進めれば、めくりながら自分で九九表を1行ずつ埋めていくことになる。
- **お手つき**：ちがう数をタップするとそのマスは **灰色のしみ** になって残る。消えない。
  正解36マスを全部めくっても、しみが1つでもあれば「かんせい」にはならず、コレクションにも入らない。
  → 叱らずに「よごれちゃった」が目に見える。「もういちど」で作り直せる。
- 36マスめくれた瞬間、まわりのカードが消え、**穴の9マスも一緒に開き**、
  マスの隙間も閉じて絵がつながって現れる（絵はここで完全になる＝ごほうび）。
- 完成した絵は「あつめた え」に貯まる（未完成は「？」でネタバレしない）。

## 絵の一覧

| 段 | 絵 | 段 | 絵 |
|---|---|---|---|
| 2 | ハート | 6 | つき |
| 3 | ほし | 7 | き |
| 4 | ねこ | 8 | いえ |
| 5 | さかな | 9 | ロケット |

絵は `art/*.png`（Codex に描かせた 1024×1024・純白背景の PNG）。
めくれたマスは、その絵の 1/10 × 1/10 を CSS の `background-position` で切り出して表示している。

## 絵を足す・差しかえる

1. `art/` に純白背景・正方形の PNG を置く
2. `build_art.py` の `PLAN` に `(段, ファイル名, 表示名)` を足す
3. `python3 build_art.py` を実行

`build_art.py` がやること：

- 白飛ばし → トリム → 正方形の中央に寄せて 1024×1024 に統一（`art/` を上書き）
- 10×10 の各マスの「絵がある割合」を計算し、**濃い順に45マス**を選ぶ
- その45マスを **`index.html` と `app-src/src/lib/art.ts` の両方**の
  `/* ART-START */ 〜 /* ART-END */` に書き戻す（片方だけ古くならないように）
- `art/_preview_*.png` に「めくり終わった状態」の確認画像を出す

## 操作

- **カードをタップ** … こたえならめくれる／ちがえば灰色のしみ
- **ヒント** … 九九のこたえを 見せる／かくす（どのマスかは教えない）
- **はじめから** … 同じ盤面をやり直す
- **ばんめん を つくりなおす** … 数の並びを作り直す
- **🔊** … 音のオン／オフ

## 部屋版のつかいかた

### 先生

1. `https://<本番URL>/sensei-9999` を開き、**かぎ**を入れる（かぎは Cloudflare の Secret `SENSEI_KEY`。コードには書かない）
2. 4けたの番号とコース名を入れて「へやを つくる」
3. 部屋に入り、**よびな**（ゆい・あん…）を登録する
4. 「しまってます」を押して **あいてます** にする
5. 子どもに `https://<本番URL>/r/1234` を渡す

部屋の中では、ひとりずつのカードに **ミニ盤面・いまの段・n/36・おてつきの数** が出る。
カードをクリックすると大きく見られる。「もういちど」で全員の盤面を作りなおす。

- **もういちど** … いま作りかけの盤面を全員ぶん白紙にもどす
- **あつめた え も けす** … 子どもの端末に貯まった「あつめた え」の ✅ を消す。
  ✅ は子どもの端末（`localStorage`）にしかないので、**その子が次に画面を開いたときに**消える。
  1回押せば1回だけ効く（それ以降に集めた絵は消えない）。

### 子ども

- URL を開いて **自分の名前を押すだけ**（ログインもパスワードもない）
- **段は自分で選ぶ。** 先生は進行を止めない。終わった子から次の段へどんどん進める
- 名前は端末に覚えさせるので、次からは押さなくていい

### ひとりモード

`/solo` は部屋にも先生にもつながらない。おうちでも、部屋が閉じていても遊べる。

## つくり

### 部屋版

- Next.js（App Router）＋ Cloudflare Workers（OpenNext）＋ D1
- 子ども→先生は **ポーリング**（子は3秒ごと、先生は0.9秒ごと）。WebSocket は使わない
- 先生画面のかぎは Secret `SENSEI_KEY`（`x-sensei-key` ヘッダ）。ローカルは `.dev.vars` に置く
- `preview_urls: false`（プレビューURLから認証をすり抜けられないように）
- 持っているのは **よびな（ひらがな）と盤面の状態だけ**。個人情報は持たない

```
npm --prefix app-src run dev      # ローカル（.dev.vars の SENSEI_KEY で入れる）
npm --prefix app-src run deploy   # 本番へ
```

### 単体版

- 単一 `index.html` ＋ `art/` の画像だけ。ビルド不要、`file://` でも動く。
- 音は Web Audio API の合成音のみ（音声ファイルなし）。
- 横長 16:9（Zoom 画面共有前提）。縦画面では上下に折り返す。
- 完成した段だけ `localStorage`（`kuku-mekuri-v1`）に保存。個人情報は持たない。

## テスト

```
node --test logic.test.mjs        # 単体版（17件）
npm --prefix app-src run test     # 部屋版（21件）
```

単体版は `index.html` の `/* @pure-start 〜 @pure-end */` に囲まれた純粋ロジックだけを取り出して検証する。
部屋版は同じルールを `app-src/src/lib/game.ts` に持っていて、そちらを直接テストしている。
盤面生成・お手つき判定・九九の点灯・完成判定など。
